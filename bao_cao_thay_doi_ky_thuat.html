1. Bối Cảnh & Động Lực Kỹ Thuật LỖ HỔNG TRƯỚC ĐÓ

Trước khi nâng cấp, giao thức bắt tay UDP chỉ sử dụng X25519 ECDH thuần túy:

  • Client và Server trao đổi khóa công khai ephemeral dạng bản rõ trong gói PKT_HELLO và PKT_HELLO_ACK.
  • Nguy cơ MITM: Kẻ tấn công đứng giữa có thể đánh chặn gói tin, thay thế bằng cặp khóa công khai của chính nó để tính toán hai khóa phiên riêng biệt (một với Client, một với Server). Từ đó, kẻ tấn công hoàn toàn có thể đọc được tin nhắn, hash mật khẩu và file truyền tải mà hai bên không hề hay biết.
Giải Pháp Toàn Diện Được Triển Khai
Bổ sung cơ chế Ký số Ed25519 tĩnh (Server Identity Key) kết hợp Ghim khóa tại Client (Public Key Pinning). Server dùng khóa danh tính ký số chứng thực khóa ephemeral của phiên. Bất kỳ sự giả mạo nào từ kẻ tấn công đều bị Client phát hiện và ngắt kết nối ngay lập tức!

3. Quy Trình Bắt Tay An Toàn Mới (Handshake Sequence) CHUẨN BẢO MẬT 
[CLIENT]                                                    [SERVER]
   |                                                           |
   | --- PKT_HELLO (client_ephemeral_pub, conn_id) ---------> |
   |                                                           | (Tạo ephemeral key)
   |                                                           | (Ký: sign_server_hello)
   |                                                           |
   | <-- PKT_HELLO_ACK (server_ephemeral_pub, signature) ----- |
   |                                                           |
   | [Kiểm tra: verify_server_hello(pinned_key, ...)]          |
   |  ├─ Sai chữ ký / Giả mạo -> DROP GÓI, NGẮT KẾT NỐI         |
   |  └─ Hợp lệ -> Hoàn tất bắt tay, kích hoạt AES-256-GCM    |
   |                                                           |
   | <================== KÊNH MÃ HÓA AN TOÀN ===============> |
